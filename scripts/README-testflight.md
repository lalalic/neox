# TestFlight release for Neox

Use `scripts/testflight.py doctor` to check the Apple API Key, app/build identity and signing. Use `scripts/testflight.py release --bump` to archive, export and upload; or `scripts/testflight.py release --archive /absolute/path/to/Neox.xcarchive` to distribute an existing build. Use `scripts/testflight.py status --build NUMBER --resolve-compliance` to resolve the approved export declaration and check internal testing, and `--assign-group` to link the existing internal testers group if authorized.

The executable is a small wrapper that resolves the **one shared `apple-delivery` Skill** through `neo skill list`. The implementation is in Neo, not Neox. Per-app identifiers, the authorized tester group, and previously reviewed encryption classification are in [`apple-delivery.json`](../apple-delivery.json); no private key is in this repo. Private `.p8` stays at `~/.private_keys` on the release machine. Changing cryptography/SDKs requires a new export-compliance review: `uses_non_exempt_encryption: false` means *exempt encryption*, not necessarily *no encryption*.

The release tool checks build numbers and archive identity, validates the encryption Info.plist field for newly created builds, and uses an authenticated API Key instead of Xcode GUI login. Legacy archives without that field can be classified after upload using Apple's supported Modify a build API, but only using the app's reviewed configuration. Successful export/upload is not TestFlight installability; check Apple processing, compliance, internal group, website and iPhone. See the shared `apple-delivery` Skill for the complete workflow and evidence requirements.
